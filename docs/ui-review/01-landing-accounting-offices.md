## 2. الأخطاء المؤكدة والإصلاحات

### P0-1 — سعر غلط ومعروض دايمًا قدام عين العميل

**الدليل:** الشريط الثابت في `Home.tsx` فيه نص مكتوب يدويًا:
```
باقات تبدأ من 250 ج.م/سنة
```
لكن أرخص باقة لمكاتب المحاسبة هي `professional` بـ**500 ج.م** (`annualPiastres: 50000`). الـ250 ج.م هي `founder` وهي باقة **شركات** (`persona: "company"`).

**الأثر:** زائر مكتب محاسبة يقرأ «من 250» في شريط ملازم للشاشة، وينزل يلاقي أقل سعر 500. ده أسوأ نوع تعارض — كسر ثقة عند نقطة القرار بالظبط، ومصدر اعتراض مباشر.

**الإصلاح:** اشتق الرقم من الباقات المعروضة فعلًا، ما تكتبهوش:
```tsx
const minPrice = Math.min(...plans.map(p => p.annualPiastres));
// باقات تبدأ من {formatEgp(minPrice)} / سنة
```
بعد الفصل لصفحتين، كل صفحة تحسب من باقاتها هي.

### P0-2 — الخصم 10% موعود في الشريط ومش ظاهر على الكروت

**الدليل:** `calculateQuote` في `shared/poc.ts` بيطبق خصم 10% (`discountBps: 1000`) على المجموع. لكن `PricingSection` بيطبع السعر الخام:
```tsx
{formatEgp(price)}   // price = plan.annualPiastres
<p>اشتراك سنوي (قبل ضريبة 14% VAT)</p>
```
يعني الشريط العلوي بينده «وفّر 10% قبل نهاية الشهر»، والكروت بتعرض السعر كامل بدون شطب ولا إشارة للخصم. الخصم بيظهر لأول مرة في الـUpsell والـCheckout.

**الأثر:** الوعد اللي جذب العميل مش متحقق في المكان اللي بيقرر فيه. ده بيقتل الإحساس بالعرض ويخلي شريط العرض يبان دعاية فاضية.

**الإصلاح:** في كل كارت أثناء سريان الحملة، اعرض ثلاث سطور واضحة:
```
2,500 ج.م   ← مشطوب، بلون خافت
2,250 ج.م   ← بارز، بالأكسنت
+ 14% VAT = 2,565 ج.م إجمالي مستحق
```
وخلي عدّاد الحملة جوه قسم الأسعار نفسه، مش في الشريط العلوي بس.

### P0-3 — الأسعار بأرقام هندية داخل خط لا يحتويها

**الدليل:**
```ts
export function formatEgp(piastres: number) {
  return new Intl.NumberFormat("ar-EG", { style: "currency", currency: "EGP", ... })
}
```
`ar-EG` بيرجع أرقام هندية (`٢٥٠٠`) بصيغة عملة عربية. والناتج بيتحط في:
```tsx
<p className="font-[Inter] text-3xl font-black" dir="ltr">{formatEgp(price)}</p>
```
**خط Inter مفيهوش أرقام هندية.** فالمتصفح بيعمل fallback صامت لخط تاني، فالسعر — أهم رقم في الصفحة — بيترندر بخط مختلف عن المقصود ومختلف من جهاز لجهاز. وكمان `dir="ltr"` مع صيغة عملة عربية بيقلب موضع رمز العملة.

**ملاحظة مكمّلة:** الحاسبة بتستخدم `toLocaleString("en-US")` — يعني **نظامين أرقام مختلفين على نفس الصفحة**.

**الإصلاح:** أرقام لاتينية + تحكم كامل في العملة:
```ts
const n = new Intl.NumberFormat("ar-EG-u-nu-latn", { maximumFractionDigits: 0 });
export const formatEgp = (p: number) => `${n.format(p / 100)} ج.م`;
```
وخلي الرقم `font-[Inter] tabular-nums` والوحدة «ج.م» بخط Cairo وحجم أصغر.

### P1-1 — الترتيب بيطلب الحساب قبل الإقناع

**الدليل:** الحاسبة التفاعلية (`TaxInvoicingSimulator`) هي **أول قسم بعد الهيرو مباشرة**، وقسم الألم رقم 7، والآراء والمقارنة **بعد** الأسعار.

**الأثر:** الزائر بيتطلب منه يحرّك سلايدرات ويحسب ضرايبه قبل ما يتأكد إن المنتج ده ليه أصلًا. والدليل الاجتماعي والمقارنة — وهما أدوات إزالة الاعتراض — بيوصلوا **بعد** ما شاف السعر واتخذ قراره.

**الإصلاح — الترتيب القمعي:**
```
1  هيرو (هوك + سعر مبدئي + CTA واحد)
2  شريط ثقة بالأرقام
3  الألم — «آخر الشهر بيقلب عليك؟»
4  المنظومة (القدرات الأربع)
5  القسم البطل — مكاتب المحاسبة
6  الإصدار والمتابعة
7  شوف النظام من جوه (الحاسبة + المعاينة)
8  إزاي تبدأ — 3 خطوات
9  مفوتر مقابل الطريقة التقليدية
10 آراء العملاء
11 الأسعار
12 بلوك الضمان — لاصق تحت الأسعار
13 الإضافات
14 الليد مجنت (حاسبة المرتبات) inline
15 FAQ اعتراضات
16 الإغلاق النهائي
```
القاعدة: **كل أداة إقناع تسبق السعر، وكل أداة إزالة اعتراض تلزق بالسعر.**

### P1-2 — الباقة الأغلى هي «البطل»

**الدليل:** في `shared/poc.ts` الباقة المميزة للمكاتب هي `elite` (2500 ج.م، `featured: true`, `badge: "أفضل قيمة للمكاتب"`) — أغلى باقة في السلّم. و`useEffect` عند تحديد الشخصية بيختار الباقة المميزة تلقائيًا:

```ts
setSelectedPlanSku(getPlansForPersona(resolved).find(p => p.featured)?.sku ...)
```

**الإصلاح:** الاختيار الافتراضي = باقة الدخول (`professional`). خلي `elite` هي **مرساة السعر** (أعلى الجدول، بشارة «أفضل تكلفة للملف») وخلي البطل الموصى به `expert` (1000 ج.م) في النص. الترقية بتيجي من الداشبورد وقت ما يوصل حد السعة، مش من صدمة أول زيارة.

### P1-4 — خمس طبقات بتتنافس على انتباه واحد

**الدليل:** الصفحة بتشغّل في نفس الوقت: شريط ترويجي علوي، رأس ثابت، شريط تحويل عائم `fixed bottom-5`، بانر كوكيز `fixed bottom-20`، مودال الليد مجنت بعد **12 ثانية**، وExit-Intent.

مشاكل ملموسة:
- **تراكب:** بانر الكوكيز (`bottom-20` = 5rem) والشريط العائم (`bottom-5` = 1.25rem) الاتنين ثابتين تحت. على الموبايل بيتكدسوا ويغطوا المحتوى.
- **الليد مجنت بعد 12 ثانية** = بالظبط وقت ما القارئ الجاد بيكون داخل قسم الألم. بتقطع عليه في أحسن لحظة.
- **الشريط العائم مفيهوش زر إغلاق** — بيغطي المحتوى للأبد.

**الإصلاح:**
- الليد مجنت: شرطه **عمق تمرير ≥ 60% أو 45 ثانية**، وما يظهرش قبل حل الكوكيز، وما يظهرش لو الزائر لمس قسم الأسعار.
- الشريط العائم: زر إغلاق + يظهر بعد تعدي الهيرو بس.
- الكوكيز: يرتفع فوق الشريط العائم (`bottom-28`) أو يبقى شريط علوي رقيق.
- **قاعدة عامة: طبقة مقاطعة واحدة كل جلسة. مش تلاتة.**

### P1-5 — نفس السؤال بيتسأل مرتين + اللوجو بيفتح مودال

**الدليل:** مودال الشخصية بيفتح تلقائيًا أول زيارة، **وكمان** فيه سويتش شخصية ثابت فوق الـH1 في الهيرو. وزيادة:
```tsx
<button onClick={() => setGateOpen(true)}>  {/* اللوجو */}
```

**الأثر:** الزائر بيتطلب منه يصنّف نفسه قبل ما يقرأ أي قيمة، ومرتين. واللوجو المفروض يرجّع للرئيسية — سلوك متوقع مكسور.

### P1-6 — إعادة رسم الصفحة كلها كل ثانية

**الدليل:**
```tsx
const [now, setNow] = useState(() => Date.now());
useEffect(() => { const i = setInterval(() => setNow(Date.now()), 1000); ... }, []);
```
`now` حالة في مكوّن `Home` نفسه (96KB، كل الأقسام جوه). يعني **الشجرة كلها بتعمل re-render كل ثانية**. وزيادة:
```tsx
const liveQuote = useMemo(() => calculateQuote(..., new Date(now)), [selectedPlan, addonQuantities, now]);
```
فـ`calculateQuote` بتتنفذ كل ثانية كذلك.

**الأثر:** استهلاك بطارية ومعالج على أندرويد متوسط، وتدهور INP — وميزانية أداء المشروع نفسه mobile-first.

**الإصلاح:** اعزل العدّاد في مكوّن `<PromoCountdown />` بمؤقته الخاص، وشيل `now` من اعتماديات `liveQuote` (استخدم تاريخ ثابت للجلسة). ولازم تقسيم `Home.tsx` لمكوّنات ملفات منفصلة أصلًا — دلوقتي فيه 6 ملفات بس في `components/`.

### P1-8 — `aggregateRating` مصرّح بدون نظام تقييم ظاهر

**تحديث معتمد من المالك:** الشهادات الحالية **موافقات موثّقة وسليمة** — فمصداقية المحتوى نفسه مش المشكلة. المشكلة الباقية تقنية بحتة وخاصة بسياسة البيانات المنظمة.

**الدليل:** `client/index.html` بيصرّح `ratingValue: 4.9` و`reviewCount: 480` في الـJSON-LD، والصفحة فيها **تلات شهادات نصية بدون نظام تقييم ظاهر ولا 480 مراجعة معروضة**.

**الأثر:** سياسة البيانات المنظمة عند جوجل بتطلب إن التقييم المجمّع يكون مشتقًا من مراجعات **ظاهرة على نفس الصفحة**. الرقم 480 مش ظاهر في أي مكان، فده خطر سحب الـrich result.

**الإصلاح (اتنين على التوالي):**
1. **فورًا:** طابق `reviewCount` مع عدد المراجعات الظاهرة فعلًا (3)، أو شيل `aggregateRating` لحد ما يبقى فيه مراجعات مجمّعة معروضة. خلي `Organization` و`SoftwareApplication` و`AggregateOffer`.
2. **المسار الأصح:** بما إن الموافقات موجودة، ابنِ **بلوك مراجعات حقيقي**: لكل شهادة اسم + الصفة + المكتب + تقييم نجوم فعلي، ومعاه `Review` schema لكل واحدة. كده الـ`aggregateRating` يبقى مشروع ومطابق للسياسة، وتكسب rich result بدل ما تخسره.

### P1-9 — الشهادات صحيحة، بس شكلها بيقول العكس

**تحديث معتمد:** الشهادات معتمدة بموافقات.

**لكن ملاحظة بيعية مهمة:** الشهادات دلوقتي **نص خام + 5 نجوم مرسومة**، بدون صورة ولا صفة كاملة ولا أي علامة تحقق. الشكل ده — حتى لما يكون حقيقي 100% — بيتقرأ عند الزائر المصري كـ«كلام مكتوب». إنت بتضيّع أصل حقيقي عندك بسبب طريقة العرض.

**الإصلاح — علامات مصداقية على كل شهادة:**
- **صورة** (بورتريه مسطح 2D — راجع IMG-A3) أو أحرف أولى في دائرة بلون الهوية.
- **الصفة الكاملة + اسم المكتب** في سطر منفصل تحت الاسم، بحجم أصغر ولون خافت.
- **نتيجة محددة بالأرقام** جوه الاقتباس («وفّرت يومين في تجميع الإقرار») — الرقم بيقنع أكتر من الوصف.
- **رابط للمكتب** لو متاح ومسموح، أو شعاره.
- **شيل صف النجوم الخمس المتطابق** على الشهادات التلاتة. تقييم مثالي متطابق بيقلل المصداقية، مش بيزودها.

### P2-1 — الأنيميشن تقليدي ومفيهوش احترام لتقليل الحركة

**الدليل:** `index.css` فيه أربع كيفريمز بس: `mof-reveal`, `mof-orbit`, `mof-float`, `mof-pulse-subtle`. منهم `mof-float` و`mof-pulse-subtle` **مش مستخدمين ولا مرة**. و`mof-reveal` متطبق على **عنصرين** في الهيرو بتأخير `100ms` واحد. الباقي كله `hover:-translate-y-1` و`animate-pulse`/`animate-ping`.

والأهم: **مفيش `@media (prefers-reduced-motion: reduce)` في الملف كله.** فيه `mof-orbit` بيلف بلا نهاية 12 ثانية و`animate-ping` مستمر — مصادر دوخة حقيقية لمستخدمين حساسين للحركة، ومخالفة WCAG.

الـ`IntersectionObserver` موجود في `Home.tsx` بس **للتتبع التحليلي فقط**، مش للأنيميشن — فمفيش أي ظهور مرتبط بالتمرير.

**الإصلاح — قائمة محددة:**

1. **حجب تقليل الحركة (إجباري، أول حاجة):**
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```
2. **ظهور متتالي مرتبط بالتمرير (stagger):** `IntersectionObserver` واحد يحط `.is-visible`، والأبناء يتحركوا بتأخير متدرج `--i * 70ms`. مش كل العناصر مع بعض.
3. **عدّاد تصاعدي على الأسعار:** لما كارت الأسعار يدخل الشاشة، الرقم يعدّ من 0 لسعره في 600ms بمنحنى `cubic-bezier(.16,1,.3,1)`. أقوى حركة ممكنة في صفحة بيع — بتجبر العين تقرأ الرقم.
4. **حركة الختم بدل الظهور العادي:** عنصر الهوية عندك هو **الختم**. خلي تأكيد الاختيار يكون «نزلة ختم» — `scale(1.4) rotate(-8deg)` → `scale(1) rotate(-3deg)` مع ظل يتجمع، 260ms. ده أنيميشن مبتكر ومشتق من الهوية نفسها، مش قالب جاهز.
5. **الخط المنقّط (Perforation) كخط تقدم:** `mof-perforation-h` معرَّف في الـCSS و**مش مستخدم**. استخدمه كخط يتعبّى بالتدريج بين خطوات «إزاي تبدأ» — عنصر هوية أصلي بيشرح تقدم.
6. **مغناطيسية خفيفة على الـCTA الأساسي:** إزاحة 4px ناحية الماوس + `scale(1.03)`. تُلغى تمامًا على اللمس وتحت `prefers-reduced-motion`.
7. **شيل `animate-ping` المستمر** من الشريط العائم — نقطة بتنبض للأبد = ضجيج بصري، مش إلحاح.

### P2-2 — الهوية: عناصر مبنية ومهجورة + انفلات لوني

**مبني ومش مستخدم في `index.css`:** `mof-perforation-h`, `mof-perforation-v`, `mof-stamp-badge`, `mof-glass-card`, `mof-glass-dark`, `mof-glow-primary`, `mof-grid-dark`, `mof-float`, `mof-pulse-subtle`, و**`.font-jomhuria`**.

**الأخطر:** خط **Jomhuria** — الخط الأساسي في دليل الهوية — بيتم تحميله في `client/index.html` و**مش بيتطبق على أي عنصر**. يعني تحميل شبكة زيادة مقابل صفر استفادة، وغياب كامل للطابع البصري للعلامة في العناوين.

**زاوية الختم:** الدليل بيقول **3° عكس عقارب الساعة**؛ الكود بيستخدم `rotate(-2.5deg)`. توحّد على `-3deg`.

**الانفلات اللوني:** الهوية أربع ألوان (`#4046B5`, `#ECECF7`, `#07081A`, `#FFFFFF`). الصفحة بتستخدم زيادة: `#10B981`, `#38ef7d`, `#F59E0B`, `#f3b750`, `#e6b75b`, `#EF4444`, `#25D366`, `#986408`, `#b84025`. تسعة ألوان خارج الهوية، متفرقة بلا وظيفة موحدة.

**الإصلاح — أكسنت واحد للقرار:** اختار **أخضر واحد** (`#10B981`) ويكون **محجوز حصريًا** لثلاث حالات: العنصر المختار، تأكيد نجاح، والسعر النهائي. أي استخدام تاني للأخضر يتشال. الكهرماني يتحصر في «قريبًا» بس. الأحمر للأخطاء بس. كده لما العميل يشوف أخضر يعرف فورًا «ده اللي اخترته / ده المطلوب» — وهو بالظبط هدف تسهيل القرار.

**تناقض اسم العلامة:** الصفحة بتشحن **«مفوتر»** و**«موفوتر»** مع بعض: `poc.ar.json` → `"name": "مفوتر"`، `alt="مفوتر"` في اللوجو، و`layout.firm.pain.callout` فيها «مفوتر»؛ بينما باقي الصفحة كلها «موفوتر». وحّد على إملاء واحد في كل الملفات.

### P2-3 — كوبي مكرر، وكوبي ميت، وكوبي بديل مشحون كنهائي

- **تكرار حرفي:** `layout.firm.pain.callout` و`layout.firm.value.title` نفس الجملة بالحرف: «الشغل ده كله مش محتاج شطارة، محتاج نظام منظم. وده بالظبط اللي مفوتر بيعمله.»
- **كوبي ميت (معرَّف ومش مرندر):** `layout.firm.pain.callout`, `layout.*.workspace`, `layout.journey`, `layout.trust`, `layout.demo` بالكامل, `sales.decision`, `sales.common`, `sales.why`, `sales.pricing.from/included/decision`, و`core.hero.*` كله (الهيرو بياخد من `sales`, مش من `core`).
- **بديل مشحون كنهائي:** في `claims.ar.json` كل القدرات الأربع `isPlaceholder: true`، وكذلك `issuance` و`onboarding` و3 من 4 بنود `pricing`. يعني **قسم القدرات بالكامل نص بديل**.

**الأثر:** ملفات الكوبي بقت مقلب. أي تعديل بيعي بيبقى مقامرة — مش واضح إيه اللي بيظهر فعلًا.

**الإصلاح:** امسح المفاتيح الميتة. وخلي `isPlaceholder: true` **يمنع البناء للإنتاج** أو يرندر شارة «مسودة» ظاهرة في بيئة التطوير. الكوبي البديل اللي بيوصل للعميل أخطر من الكوبي الناقص.

## 3. الـSEO — بعد الفصل لصفحتين

### العائق الجذري
`client/index.html` فيه **`<title>` و`<meta description>` ثابتين للتطبيق كله**. مع صفحتين هبوط، الاتنين هيبقى لهم نفس العنوان والوصف = محتوى مكرر، ويستحيل ترتيبهم على نيّات بحث مختلفة. والمشروع SPA (Vite + React) بدون تصيير مسبق، فالزاحف بيشوف `<div id="root"></div>` فاضية.

**الإصلاح الإلزامي:** تصيير مسبق (pre-render) أو SSR للمسارات العامة الثلاثة `/`, `/accounting-offices`, `/companies`، مع وسوم لكل مسار.

### وسوم LP-A المقترحة
```html
<title>برنامج مكاتب المحاسبة والضرائب في مصر | موفوتر</title>
<meta name="description" content="أدر ملفات عملائك الضريبية من مكان واحد: قراءة بوابة مصلحة الضرائب، تجهيز تقارير VAT ونموذج 41، وصلاحيات لفريق المكتب. باقات من 500 ج.م سنويًا." />
<link rel="canonical" href="https://mofawtar.com/accounting-offices" />
```
**H1 الوحيد:** «إدارة ملفات عملاء مكتب المحاسبة من مكان واحد» — يحتوي نية البحث الأساسية.

### أخطاء SEO مؤكدة في `client/index.html`

| # | الخطأ | الإصلاح |

## 5. Persona Gate — على `/`

**الحالة الحالية:** `Dialog` جوه `Home.tsx`، بيفتح تلقائيًا لو مفيش `?p=` ولا `localStorage.mof_persona`. الكوبي في `sales.gate`، والتتبع كامل (`persona_gate_shown`, `persona_selected`, `persona_gate_skipped`).

**مشاكل:**
1. **باراميتر غير متسق:** الهيرو بيقرأ `?p=firm`، لكن `continueToCheckout` بيكتب `/checkout?persona=firm`، و`Checkout.tsx` بيقرأ `?persona=`. اسمين لنفس المفهوم → أي لينك حملة مكتوب بـ`persona=` مش هيشتغل على الهبوط. **وحّد على `persona=`.**
2. **زر «أكمل كزائر»** بيقفل المودال ويسيب الشخصية على `firm` الافتراضية بدون تسجيل تفضيل — فزائر شركة بيشوف باقات مكاتب.
3. الكوبي فصحى: «تستخدم موفوتر لإدارة ماذا؟» — والاستراتيجية بتطلب مصري.

**التصميم المقترح لـ`/`:**
- شاشة كاملة نظيفة، بدون رأس ولا شريط ترويجي ولا كوكيز مقاطع.
- H1: **«انت بتدير ملفات عملاء، ولا ملف شركتك؟»**
- كرتين كبيرتين متساويتين، وكل واحدة بتقول للزائر مكسبه لا تصنيفه:
  - **«عندي مكتب محاسبة»** — بدير ملفات ضريبية لأكتر من عميل وفريق بيتابع معايا → `/accounting-offices`
  - **«عندي شركة أو بشتغل لحسابي»** — بنظم ملف ضريبي واحد وعمليات يومية → `/companies`
- تحتهم سطر صغير: «مش متأكد؟ ابدأ من نسخة الشركات، وتقدر تبدّل في أي وقت.»
- **تحويل تلقائي** لو الـUTM أو `?persona=` محدد، والـgate تتخطى بالكامل.
- الـgate تُحفظ في `localStorage` وتُحقن في كل حدث تتبع (موجود فعلًا ✅).
- **مهم للـSEO:** `/` تبقى `noindex` أو تحويل 302 بحسب الشخصية؛ الصفحتين هما الأصول القابلة للفهرسة.
